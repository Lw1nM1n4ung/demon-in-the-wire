## BUG #6 — IDOR guard over-reached to team-cooperative `@action` endpoints

**Severity**: MEDIUM (functional regression, blocked legit team-cooperation flows)
**Introduced by**: `a7f6b5f` (earlier in this session)
**Status**: FIXED — commit `ba5001e`

### Reproduction (Phase 5, engineer → admin-owned scan/policy)

```
engineer POST /api/scans/<admin>/cancel/             → 403 (want 200)
engineer POST /api/scans/<admin>/regenerate_reports/ → 403 (want 400-not-completed)
engineer POST /api/policies/<admin>/clone/           → 403 (want 201)
```

### Root cause

`IsCreatorOrOwnerForWrite.has_object_permission()` fired on every unsafe HTTP method:

```python
def has_object_permission(self, request, view, obj):
    if request.method in ('GET', 'HEAD', 'OPTIONS'):
        return True
    if getattr(request.user, 'role', '') == 'owner':
        return True
    return getattr(obj, 'created_by_id', None) == request.user.id
```

That blanket-blocks every `@action(detail=True, methods=['post'])` handler — including the team-cooperative ones that don't destroy the row they operate on. `/clone/` is the clearest example: it creates a *new* policy owned by the caller; it never mutates the source. Blocking it makes every engineer unable to fork a shared policy template.

Original bug was DELETE (destruction of audit trail). My fix over-matched.

### Fix

Narrowed the guard to `destroy` / `update` / `partial_update` (the actions that actually erase or overwrite the row). Custom `@action` POSTs are team-cooperative business-logic endpoints; their view methods ship with their own semantics and can add ownership checks if a specific action needs them.

```python
_DESTRUCTIVE = frozenset(('destroy', 'update', 'partial_update'))

def has_object_permission(self, request, view, obj):
    if request.method in ('GET', 'HEAD', 'OPTIONS'):
        return True
    if getattr(view, 'action', None) not in self._DESTRUCTIVE:
        return True
    if getattr(request.user, 'role', '') == 'owner':
        return True
    return getattr(obj, 'created_by_id', None) == request.user.id
```

### Regression matrix (post-fix)

Engineer on admin-owned resources:

```
DELETE /api/scans/<admin>/           → 403  (IDOR guard holds)
DELETE /api/policies/<admin>/        → 403  (IDOR guard holds)
PATCH  /api/policies/<admin>/        → 403  (IDOR guard holds)
POST   /api/scans/<admin>/cancel/            → 200  (team-cooperate unblocked)
POST   /api/scans/<admin>/regenerate_reports/→ 400  (scan-incomplete; passed perm check)
POST   /api/policies/<admin>/clone/          → 201  (clone creates new row owned by engineer)
DELETE /api/scans/<own>/             → 204  (self-write preserved)
```

Viewer cells still 403 across the board (role check fires before object check).

## What else the audit confirmed

### Phase 1 — SPA routing (every role × 20 routes)
- `GET /` → 302 unauth / 200 all authed roles. **Regression test for the `f198371` nginx fix — holds.**
- `GET /nonexistent-sink` → 302 unauth / 200 authed (History-API fallback to `/app.html` works).
- `GET /login`, `/setup` → 200 for everyone (Tier-0 pages public).
- Tier-1 SPA routes (`/scans`, `/hosts`, `/policies`, `/users` etc.) all return 200 to any authenticated role — client-side `WG._canVisit()` handles per-role redirection after render. No server-level role gate at this layer, which is intentional (nginx doesn't know the user's role; only the session validity).

### Phase 2 — Static assets
- `/css/*`, `/js/public/*`, `/js/lib/*` → 200 for everyone, including unauth (CSS and the login/setup boot scripts must be publicly fetchable).
- `/js/app/router.js`, `/js/app/auth.js`, `/js/app/pages/*` → 403 unauth / 200 authed via nginx `auth_request /_auth_check` + `@forbidden_js`. Gate still works.

### Phase 3 — Blocked paths
- `/admin`, `/admin/`, `/admin/foo`, `/ADMIN` → 404 for everyone. `location ~* ^/admin` (case-insensitive regex) is correct.
- `/.env`, `/Dockerfile` → 404. Dotfile + sensitive-file block holds.

### Phase 4 — API read endpoints (26 paths × 4 roles)
Every cell matched its expected code. Highlights:
- Public (`/api/auth/csrf/`, `/api/site-config/`, `/api/auth/check-username/`) → 200 everyone.
- `/api/auth/check/` → 401 unauth / 204 auth (nginx `auth_request` probe wire).
- Admin-only (`/api/auth/users/`, `/api/audit-log/`) → 401 unauth / 403 non-owner / 200 owner.
- Scan-read tier (`/api/scans/`, `/api/hosts/`, `/api/assets/`, `/api/policies/`, `/api/schedules/`) → 401 / 403 / 200 / 200.
- Finding-read (`/api/findings/`) → available to all three roles (403 unauth only) — viewer CAN see findings but not scans themselves, matching the RBAC spec.

### Phase 5 — API mutations
Pre-fix: 3 deviations (BUG #6 above).
Post-fix: 26/26 cells match. Including the owner-only paths:
- `POST /api/support-bundle/` → 200 owner / 403 non-owner / 401 unauth.
- `POST /api/site-config/reset-setup/` → 403 non-owner (we did NOT test the 200 owner case — destructive, would wipe the portal).
- `POST /api/auth/users/create/` → 201 owner / 403 engineer / 401 unauth.
- `POST /api/auth/setup-admin/` after setup-complete → 403 for everyone.
