## Findings & fixes

### F2 · P0 — session-killer on any 403 (FIXED)
`api.js` treated every 401/403 as session expiry and logged the user out. A Viewer hitting the dashboard triggered `/api/assets/` → 403 (correct role gate), but the frontend killed the session and bounced them to `#login`. Viewers could not stay logged in.  
**Fix:** `web/js/api.js` — only 401 clears the session. 403 returns null and lets the caller handle it.

### F1 · P1 — sidebar badges permanently stuck on "0" (FIXED)
After the ASM dashboard rewrite, nothing updated the Scans / Findings badges in the sidebar. They displayed hardcoded "0" on every page forever.  
**Fix:** `web/index.html` hides them by default; `web/js/pages/dashboard.js::_updateSidebarBadges` populates them from the dashboard KPI response and re-hides when zero.

### F3 · P1 — Viewer dashboard noise (FIXED)
Viewer's dashboard load fired `/api/assets/` which always returned 403 (no `host:read` permission). Showed up as a console error on every Viewer dashboard render.  
**Fix:** `web/js/pages/dashboard.js` — `_dashboardCanViewAssets()` helper gates both the `/assets/` fetch and the Asset Inventory panel render so Viewers skip both.

### F4 · P1 — Viewer saw "+ New Scan" button (FIXED)
Dashboard header showed the scan-launch CTA to Viewers even though submitting would 403.  
**Fix:** same `_dashboardCanViewAssets()` gate on the header button.

### F5 · P1 — stray `/auth/users/` on navigation race (FIXED, defense-in-depth)
Residual 403 on `/api/auth/users/` appeared during role-switching races.  
**Fix:** `web/js/pages/users.js::renderUsers` now short-circuits with an "Owner access required" state when `role !== 'owner'`, matching the settings Administration tab. The router gate remains as the first line of defense.
